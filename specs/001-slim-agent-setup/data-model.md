# Data Model: Slim the agent-setup skill

## Template values

Gathered by the skill in its Look step, written to a temporary JSON file, and passed to the
renderer.

| Field | Required | Source | Change |
| --- | --- | --- | --- |
| `project` | yes | One sentence from the README or package manifest | kept |
| `conventions` | yes | The instruction file holding the repo's rules, else "the patterns already in the code" | kept |
| `gate` | yes | The check a pull-request workflow runs, else a known fallback list | kept |
| `gate_scopes` | no | A smaller check per area, when the repo defines one | kept |
| `default_branch` | yes | `origin/HEAD`, else the branch the user names | kept |
| `worktree_note` | yes | Worktree command and location, branch and commit rules, merge rule | kept, Serena addendum cut |
| `framework_note` | yes | Framework detection | **removed** (FR-002) |
| `implement_note` | yes | Framework implement skill | **removed** (FR-002) |
| `review_note` | no | Framework review skill | **removed** (FR-002) |

Validation: every required field is non-empty after trimming; no value contains `'''` (Codex
TOML literal). A missing required field exits non-zero naming the field.

## Agent definition

One per agent per host. Metadata is held to parity with the current version (FR-005).

| Agent | Claude `tools` | Claude `skills` | Cursor `readonly` | Codex `sandbox_mode` |
| --- | --- | --- | --- | --- |
| builder | Read, Grep, Glob, Bash, Edit, Write, Skill | follow-the-rules | false | workspace-write |
| reviewer | Read, Grep, Glob, Bash, Skill | — | false | workspace-write |
| hall-monitor | Read, Grep, Glob, Bash, Skill | follow-the-rules | true | read-only |

Paths per host:

| Host | Agent file |
| --- | --- |
| Claude Code | `.claude/agents/<name>.md` |
| Cursor | `.cursor/agents/<name>.md` |
| Codex | `.codex/agents/<name>.toml` |

Every file ends with the marker `Generated by agent-setup.`. Descriptions change from "started
only from the orchestrate skill's loop" to "started only by the orchestrator".

## Orchestrator entry point

Replaces the `orchestrate` skill and the instruction block. Per host, see
[research.md](research.md) decision R1 for the mechanism.

| Host | Definition | Start-up setting | Pending spike |
| --- | --- | --- | --- |
| Claude Code | `.claude/agents/orchestrator.md` | `"agent": "orchestrator"` in `.claude/settings.json` | S1 |
| Codex | marker-wrapped `developer_instructions` block | same block, top of `.codex/config.toml` | S2 |
| Cursor | `.cursor/rules/orchestrator.mdc` | `alwaysApply: true` in its frontmatter | S3 |

A host whose spike fails falls back to report-only: no start-up setting is written, and the report
says how to start the orchestrator there (FR-004).

The orchestrator definition carries the marker. A start-up setting lives in a file the user may
also own, so the renderer edits only its own key and refuses when the key already names another
agent, unless forced.

## Legacy artifacts

Written by earlier versions; setup and remove both clear them when they carry the marker.

| Artifact | Where |
| --- | --- |
| `orchestrate` skill | `.claude/skills/orchestrate/`, `.agents/skills/orchestrate/`, `.cursor/skills/orchestrate/` |
| Instruction block | Between `<!-- agent-setup:start -->` and `<!-- agent-setup:end -->` in any file |
| `orchestrator` agent (pre-orchestrate versions) | Same paths as agent definitions; replaced by the new orchestrator definition |

Lifecycle: `absent → written (setup) → rewritten (rerun) → absent (remove)`. A file without the
marker at a target path blocks setup unless forced, and is never removed.
